# ライブラリ移行失敗からの復旧（2026-10-11）

スクリーンショットでは、Ongaku Media内のOngaku Library Dataを作成する権限がなく、起動時の移行が中断していた。元の画面にはエラー表示だけで、再認可する操作がなかった。権限が失われた具体的な原因（bookmark、sandbox、OS側の権限など）はスクリーンショットだけでは確定できない。

## 実装

- エラー画面に現在のメディアフォルダのパスと「フォルダを選択して再試行」を追加。
- NSOpenPanelで同じ保存先を選択する。別のフォルダは作成や移行を始める前に拒否する。
- 既存のactivateDirectory経路でsecurity scopeを開始し、移行成功後にbookmarkを保存する。失敗時は前のストレージ設定を維持する。
- 既存の段階的な移行処理を再試行し、失敗時のmigrationErrorを保持する。成功すると起動時の読み込みtaskを再実行する。
- 英語・日本語・简体中文の説明を更新し、再起動だけを指示する状態を解消する。

## 検証

`swift test --filter ApplicationSettingsTests`: 19テスト成功。フォルダの代わりにファイルがある失敗状態から、同じインスタンスで復旧する試験を拡張した。異なるフォルダの拒否、失敗時の元データ保持、再試行成功、繰り返し復旧、再起動後の同じカタログ復元を確認する。同じフォルダのURL末尾スラッシュ表記差も許容する。

ログ: `/tmp/ongaku-migration-recovery-final-tests.log`。

App Store schemeのDebugビルド（arm64／x86_64、CODE_SIGNING_ALLOWED=NO）も成功。ログ: `/tmp/ongaku-migration-recovery-build.log`。署名なしのビルド成功はsandbox権限回復の保証にはしない。

⭕️ [Pending] 署名されたsandboxアプリでNSOpenPanel選択による実際のアクセス権回復と復旧画面の実表示。単体試験はsandbox権限そのものを再現しない。OSのACL・読み取り専用ボリューム・空き容量不足はフォルダ選択だけでは解消しない。利用者の実ライブラリは試験で変更していない。

## 追加修正: 親フォルダ経由の再認可と表示省略

2枚目のスクリーンショットでは再試行後にフォルダ再選択の説明が表示され、見出しも省略されていた。前実装はパスの完全一致しか許容せず、親フォルダを選択した場合に拒否していた。

現在は保存先自身または保存先を含む親フォルダを許可し、シンボリックリンク解決後のパスで確認する。パス接頭辞にはディレクトリ区切りを含め、Media-otherなど別フォルダは許可しない。フォルダ選択の権限と実際の保存先を分離し、選択した親へ保存先を変更しない。選択フォルダのbookmarkを保存先パスごとに保持し、起動時のprofile移行より前に復元する。失敗時は既存の認可設定を維持する。

エラー見出しと詳細を縦方向に折り返して全文表示する。認可説明を英語・日本語・简体中文で更新した。

設定19テストで、親・同じフォルダ・シンボリックリンク、別フォルダ拒否、保存先維持、復旧と再起動を検証。実sandboxの権限回復は引き続き ⭕️ [Pending]。

## 自動検出と保存先参照の修復

パス表記の検査だけでは復旧しなかったため、NSOpenPanelで認可した範囲の中をバックグラウンドで調べる。既存のOngaku Media／Ongaku Library Data／library-v1.jsonを検出し、保存済みカタログのlibraryIDが読み取れる場合は一致する候補を選ぶ。保存済みの場所が見つかれば優先し、それ以外は候補が1つの場合だけ場所の参照を修正する。旧カタログが存在する場合は、既存のOngaku Mediaへの移行再開も可能。

検索は深さ5・最大4,096フォルダで制限し、見つかったライブラリ内部やシンボリックリンクの先は巡回しない。見つからない／複数候補／範囲が大きすぎる場合は理由を三言語で表示する。空のライブラリを勝手に作らない。確認中の表示と「フォルダを選択して自動修復」ボタンを追加する。

修復は既存の移行処理を使い、成功後は修正されたカタログに接続して読み込みを再開する。失敗時はprofileの参照を元に戻す。復旧時はactive profileだけを移行し、起動時もinactive profileの失敗でactive profileを停止しない。inactiveの元データは保持し、未移行profileがある場合は共用アートワークを削除しない。

設定20テスト成功。移動した保存先の検出と参照修正、元カタログの内容保持、複数候補／未検出、既知の保存先優先、別profileのアクセス障害を伴う再起動を検証した。単体試験は実sandboxや実ボリュームの書込制限を再現しない。OSの書込制限を無条件に変更する処理は追加していない。
