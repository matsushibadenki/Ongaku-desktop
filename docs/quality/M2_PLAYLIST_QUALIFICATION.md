# M2 プレイリストと整理の終了判定

M2は、各機能が単独で動くだけでなく、Undo／Redo、永続化、楽曲の移動、メタデータ編集をまたいでもプレイリストの曲参照が同じ楽曲IDを維持できた時点で完了とする。

## 自動ゲート

| 状態 | 試験 | 合格条件 |
|---|---|---|
| [Done] | 通常プレイリスト | 作成、名称・説明・画像編集、複製、削除をそれぞれUndo／Redoできる |
| [Done] | 曲の構成 | 曲追加、曲削除、曲順変更をそれぞれUndo／Redoし、順序と楽曲IDが正確に戻る |
| [Done] | フォルダ整理 | フォルダ作成、名称変更、プレイリストの所属変更、フォルダ順変更、フォルダ削除をそれぞれUndo／Redoできる |
| [Done] | 再起動 | 一連の編集後に新しいRepositoryとStoreを生成し、プレイリスト、曲順、フォルダ構成が復元される |
| [Done] | 楽曲移動 | 音声ファイルを別パスへ移動してチェックサム照合で再リンクしても、プレイリストが同じ楽曲IDを解決する |
| [Done] | メタデータ変更 | 曲名、アーティスト、アルバムを変更しても参照を維持し、再起動後も変更後の楽曲を解決する |
| [Done] | 回帰 | Swift全テストとmacOS製品ビルドを通過する |

自動試験は`M2PlaylistMilestoneTests`に置き、通常の`swift test`とGitHub Actionsから毎回実行する。プレイリスト参照は表示名やファイルパスではなく不変の`Track.ID`を正本とし、ファイル移動とメタデータ変更から分離する。

## 配布候補での確認

| 状態 | 環境 | 確認内容 |
|---|---|---|
| [Later] | 大規模実ライブラリ | 10万曲規模、数千プレイリストでサイドバー操作、複数選択、ドラッグ＆ドロップ、Undo履歴の操作感を確認する |
| [Later] | 外付け音源 | ボリュームの取り外し、再接続、別マウントパスへの変更を含め、再リンク後のプレイリスト表示を実機確認する |

大規模性能はM3、長時間運用と配布候補の実機回帰はM10で再確認する。M2では参照整合性と操作の可逆性を決定論的な統合試験で保証する。
