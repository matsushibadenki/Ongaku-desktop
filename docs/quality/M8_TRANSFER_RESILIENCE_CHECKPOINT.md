# M8 転送堅牢化チェックポイント

M8の端末同期は、転送中に利用者が現在位置を確認して安全に停止でき、容量不足や接続断が起きても未検証ファイルをライブラリへ確定しない段階まで進んだ。

## [Done] 今回の保証

| 項目 | 保証 |
| --- | --- |
| 進捗 | MacとiPhoneの送受信で割合、転送済み容量、総容量を表示する |
| 一時停止・再開 | 暗号化された同一接続内で送信側と受信側を同じ制御状態にする |
| キャンセル | 双方の転送処理を止め、キャンセル済みとして失敗と区別する |
| 容量不足 | 受信前に256MBの安全余白を残して判定し、不足時は双方へ通知する |
| 接続断 | 実行中の転送を中断として明示し、未検証ファイルをライブラリへ登録しない |
| 完全性 | ファイルサイズとSHA-256が一致した受信ファイルだけを確定する |
| チャンク | 256KiBごとにSHA-256を検証し、破損チャンクはチェックポイントへ記録しない |
| 永続再開 | 検証済みチャンクをApplication Supportへ原子的に保存し、同じ曲の再要求時は不足分だけを要求する |
| 容量管理 | 未完了転送の曲名、進捗、保存容量を表示し、30日後に自動失効、一括破棄も提供する |
| 表示 | 状態と操作を英語、日本語、简体中文で提供する |

## [Next] 次の境界

- 実機で容量不足、破損、Wi-Fi切断、バックグラウンド遷移を検証する
- 実機の大容量音源で再開時間、メモリ使用量、Multipeer Connectivityの送信安定性を計測する

同一接続内では一時停止ボタンから直ちに再開できる。接続断またはアプリ終了後は、再接続して同じ曲をもう一度要求すると、保存済みチェックポイントを照合して不足チャンクから再開する。実機での終了条件確認は次のチェックポイントで行う。
