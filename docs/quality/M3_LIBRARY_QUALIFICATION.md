# M3 ライブラリ管理の終了判定

M3は、メタデータ編集・歌詞・重複整理・検索・複数ライブラリが揃い、10万曲でも起動時表示と一般検索の性能目標を満たし、削除前に対象と復旧可否を判断できた時点で完了とする。

## 自動ゲート

| 状態 | 試験 | 合格条件 |
|---|---|---|
| [Done] | 10万曲コールド表示 | 10回実測のp95で2秒目標を満たし、CI単独試験では共有ホストのI/O変動を含む退行上限4秒未満 |
| [Done] | 10万曲一般検索 | SQLite索引で曲名、アーティスト、アルバム、日本語曲名を検索し、95パーセンタイル300 ms未満 |
| [Done] | 削除対象 | 重複整理の確認画面に、保持曲を除いて登録解除する正確な件数と、画面上で確認できる各候補を表示 |
| [Done] | 復旧可否 | Ongaku Media内の管理ファイルだけをゴミ箱へ移して復元可能にし、外部参照ファイルは変更しない |
| [Done] | 三言語 | 削除対象・外部参照の保護・ゴミ箱からの復旧説明を英語、日本語、简体中文で同じ書式引数により表示 |
| [Done] | 回帰 | Swift全テストとmacOS製品・UIテストのコンパイルゲートを通過する |

自動試験は`LargeLibraryPerformanceTests.m3PerformanceGate`と`M3LibraryManagementMilestoneTests`に置く。性能ゲートは`ONGAKU_ENFORCE_M3_PERFORMANCE=1`を指定してCIで単独実行し、他テストの並列I/Oを測定値へ混ぜない。索引の初回作成時間は検索応答から分離する一方、初期表示には実際のJSON読み込みを含める。

## 10万曲カタログ最適化

`Track`のJSONは、空文字、`false`、0などデコーダーが既定値を補える項目を新規保存時に省略する。さらに整形とキー並べ替えを外し、スキーマ12と旧カタログの読み込み互換性、原子的書き込み、検証済みバックアップを維持する。

2026年8月31日の開発機実測では、マニフェストを約117.5 MBから約49.0 MBへ削減し、10回測定のコールドロードp95を4.210秒から1.385秒へ短縮した。SQLite検索p95は0.816 msだった。

| 状態 | 環境 | 確認内容 |
|---|---|---|
| [Later] | 低速外付けボリューム | 10万曲カタログと音源を低速ストレージへ置き、起動、検索、再リンクの体感と劣化時表示を確認する |
| [Later] | 監視フォルダ | 永続セキュリティスコープ、再帰監視、変更中ファイルの安定待ち、競合プレビューを一体で設計し、M5のローカル完全版で実装する |

監視フォルダは無断の上書きや読み込み途中のファイル登録を避けるため、単純な周期スキャンとしてM3へ入れず、明示的な競合解決と復旧手段を備えるM5項目へ移す。
