# 同期保存・再接続の追補 — 2026-11-12

## 原因と実装

1. Macのresource送信完了はiPhoneへの保存完了ではなかった。manifestへ任意のsupportsResourceReceipts／resourceReceiptsを追加。更新iPhoneは転送ID・SHA-256・エラー有無を返す。Macは通信完了と保存確認の両方を待つ。通知が先着してもよい。旧iPhoneは検証後のmanifestにハッシュが含まれることを確認。確認待ち120秒で失敗、ID削除で二重完了を防ぐ。切断した接続世代の完了で新しい一括同期を進めない。
2. 重複判定のハッシュ更新が全走査後まで遅れていた。iPhoneはMCSessionの一時URLをコールバック中に自身の一時領域へ移し、Taskチェーンで検証・保存・増分インデックス更新を直列化。サイズ／SHA-256／対応拡張子／読込結果を検証後、同じボリューム内のrenameで公開。重複は既存ファイルの存在も確認。失敗時に一時ファイルを回収。
3. 毎曲の全曲ハッシュ再計算を廃止。既存の全走査は画面開始時などだけにし、受信保存のrevisionと走査generationで古い結果を拒否。アプリ側ライブラリの再表示通知は0.5秒で集約。タグなし曲で一時ファイル名を表示しないよう、同期表示は送信元の曲情報を維持。
4. iPhoneの再試行は待受けの再起動だけで、Macはsearching以外や自動招待の5分待機中に再招待しなかった。明示的な操作だけでUUIDのreconnectRequestを更新し、Macは新しいトークンを1回だけ受理して再招待。広告の周期再起動でトークンは変えない。接続中／承認中の再試行は抑止。古い広告インスタンスからの招待・失敗通知を無視。初回画面表示でハッシュ計算を待たずに広告開始。
