# A4 保存完了・失敗とライブラリの所有権 — 2026-11-03

## 優先理由と再現

保存先切り替え後の古い非同期処理が、新しいライブラリの画面状態を更新する経路を優先した。履歴消去の保存をFileManagerのディレクトリ準備で一時停止し、その間に別ライブラリへ切り替え、古い書き込みを権限エラーで失敗させた。変更前は `clearPlaybackHistory` のcatchが古い履歴を新しい画面へ復元し、新ライブラリの履歴ID比較で失敗した。台帳自体の新ライブラリ側は無変更で、問題はメモリ側の巻き戻しに再現した。

## 変更

- 🟢 [Done] 履歴の記録失敗と履歴消去失敗は、開始時のストレージ世代が一致する場合だけ画面状態を巻き戻す。切り替え準備中は新たな履歴操作を開始しない。
- 🟢 [Done] メタデータ・歌詞・プレイリストの保存先Repositoryを開始時に捕捉。ファイル埋め込みを含む待機中にライブラリが変わっても、旧保存先の処理が新保存先へ保存しない。完了後の画面更新・成功通知・Undo登録は世代一致時だけ実施し、古い呼出元にはCancellationErrorを返す。
- 🟢 [Done] プレイリスト画像の後始末も開始時のRepositoryへ固定。再リンクの探索結果・保存結果と、ファイル存在確認の成功／失敗による画面反映も世代照合する。

旧保存先で既に実行されたファイル変更を巻き戻す設計ではない。旧Repositoryへの保存を完了して整合性を保ちながら、新ライブラリの表示・状態へ適用しない。同期オーバーレイ、重複整理等の全更新経路の統一とA4全体の完了は、この変更から推定しない。
